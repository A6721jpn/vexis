# Config設定における潜在的リスクと対策案 (Rev.2)

## 1. 概要
`config.yaml` の設定値バリデーションが不十分であるため、ユーザーがサポート外の設定や不正な値を入力した際に、実行時の予期せぬエラーやクラッシュを引き起こすリスクがある。
本リビジョンでは、具体的なバリデーションルールと実装箇所を詳細化した。

## 2. リスク項目と具体的な対策ルール

### A. Analysis Settings (解析設定)
`AnalysisConfig` クラスを導入し、読み込み時に以下の静的チェックを行う。また、解析直前の動的チェックも追加する。

| 項目名            | バリデーションルール (対策)                                                                                                                      | 実装フェーズ                                         |
| :---------------- | :----------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------- |
| `total_stroke`    | 1. **静的**: 0 以外であること。<br>2. **動的**: **生成されたメッシュのZ軸高さ(サイズ)の 80% 以下であること**。<br>違反時はエラーとして停止する。 | 1. `AnalysisConfig`<br>2. `main.py` (メッシュ生成後) |
| `time_steps`      | **正の整数** (value > 0, int) であること。                                                                                                       | `AnalysisConfig`                                     |
| `num_threads`     | **正の整数** (value > 0, int) であること。                                                                                                       | `AnalysisConfig`                                     |
| `template_feb`    | 指定されたパスに**ファイルが存在すること**。                                                                                                     | `AnalysisConfig`                                     |
| `febio_path`      | 指定されたパスに**ファイルが存在すること**。                                                                                                     | `AnalysisConfig`                                     |
| `contact_penalty` | **0 より大きく、かつ 20 未満 (0 < value < 20)** であること。<br>20以上の値は極端すぎるためエラーとする。                                         | `AnalysisConfig`                                     |

### B. Mesh Generation Settings (メッシュ生成設定)
`MeshGenConfig` クラス (`src/mesh_gen/config.py`) を修正し、以下のルールを適用する。

| 項目名           | バリデーションルール (対策)                                                                                                                                  | 備考                                                                          |
| :--------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------- |
| `revolve_angle`  | **90.0度 (誤差許容) のみ許可する**。<br>(`abs(angle - 90.0) < 1e-6` 以外はエラー)<br>※現状のコア生成ロジックが90度回転の対称モデルにしか対応していないため。 | `main.py` のチェックは残しつつ、`config.py` で早期エラーにする (二重チェック) |
| `revolve_layers` | **5 以上 100 以下の整数** であること。<br>(`5 <= layers <= 100`)<br>極端に少ないと形状破綻、多いと計算コスト過大のため。                                     | 範囲外または非整数の場合は `ValueError`                                       |
| `output_format`  | 許可リスト: `["inp", "vtk", "msh"]` に含まれること。                                                                                                         | それ以外は `ValueError`                                                       |

## 3. 修正範囲と実装方針

### 1. `src/mesh_gen/config.py` の修正
*   **`MeshGenConfig.from_yaml`** の修正:
    *   `revolve_angle`: 90度以外の場合に `ValueError("Currently only 90.0 degrees is supported.")` を送出。
    *   `revolve_layers`: 5～100の整数範囲チェックを追加。
    *   `output_format`: 文字列リストチェックを追加。
*   **`AnalysisConfig` クラスの新規追加**:
    *   上記Aの静的チェック（型確認、値の範囲、ファイル存在確認）を行うバリデータクラスを実装する。

### 2. `main.py` の修正
*   **設定読み込みの刷新**: `full_conf.get(...)` で個別に値を取る処理を廃止し、`AnalysisConfig.from_yaml(...)` を呼び出して検証済みの設定オブジェクトを取得する形に変更。
*   **動的チェックの追加**:
    *   メッシュ生成完了後 (`Step 1` 完了後)、`total_stroke` (押し込み量) と メッシュのZ高さ (`bounding_box_z`) を比較。
    *   `abs(total_stroke) > (mesh_height_z * 0.8)` の場合、安全機構としてエラー停止させるロジックを追加。

### 3. `analysis_helpers.py`
*   `AnalysisConfig` オブジェクトを受け取れるように引数をリファクタリング（オプション）。
*   不要になった個別チェックがあれば削除し、コードをシンプルに保つ。
